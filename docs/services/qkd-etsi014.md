# QKD (ETSI GS QKD 014) & QuaDRA

This lab integrates **ETSI GS QKD 014** Key Management Entities (KMEs) on the management network and, when the QuaDRA extension is installed, **static SAK MACsec key rotation** on **ceos1-both:Ethernet2 <-> ceos3-qkd:Ethernet1** (`10.255.0.5/30` <-> `10.255.0.6/30`).

!!! danger "QuaDRA is not publicly available"
    **QuaDRA** (Quantum keys Distribution and Rotation Agent) is an **Arista EOS SDK extension** that is **not distributed in this public repository** and is **not generally available for download**.

    To obtain QuaDRA packages, documentation, and licensing for your platform, **contact your Arista account team** or Arista support.

    The sections below describe how the lab is **configured** when QuaDRA is present. Without the extension, startup-config keeps the `daemon quadra` stanza in **shutdown** and `make test-qkd` skips with a warning.

## Architecture overview

| Component | Node(s) | Role |
|-----------|---------|------|
| KME simulator `kme-a` | mgmt `:8010` | Master KME; linked to `kme-b` |
| KME simulator `kme-b` | mgmt `:8020` | Peer KME |
| **QuaDRA master** | ceos1-both | Calls `enc_keys` on `kme-a`; rotates static SAK on Ethernet2 |
| **QuaDRA slave** | ceos3-qkd | Calls `dec_keys` on `kme-b`; applies keys on Ethernet1 |

KME simulators use the open-source [next-door-key-simulator](https://github.com/CreepPork/next-door-key-simulator) (lab use only — **not for production**).

Default management addresses (override with `MGMT_SUBNET=`):

| Node | IPv4 | HTTPS API |
|------|------|-----------|
| kme-a | 172.20.127.51 | `:8010` |
| kme-b | 172.20.127.52 | `:8020` |
| ceos1-both | 172.20.127.11 | QuaDRA -> `kme-a` |
| ceos3-qkd | 172.20.127.13 | QuaDRA -> `kme-b` |

## ETSI QKD 014 KME configuration

### Docker image

Built from `docker/kme/Dockerfile` as `quantum-safe-kme:latest`. Deploy stages KME nodes first (`make deploy-kme`, `make wait-kme-pool`) so key material is ready before cEOS boots.

### PKI (generated by `make gen-topo`)

| File under `lab/.gen/kme-pki/` | Purpose |
|----------------------------------|---------|
| `ca.crt.pem` | Lab KME CA |
| `kme-a.crt.pem`, `kme-a.key.pem` | `kme-a` server certificate |
| `kme-b.crt.pem`, `kme-b.key.pem` | `kme-b` server certificate |
| `sae.crt.pem`, `sae.key.pem` | Master SAE client (CN = locked SAE ID) |
| `sae-b.crt.pem`, `sae-b.key.pem` | Slave SAE client |
| `kme-sae-bundle.pem`, `kme-sae-b-bundle.pem` | Concatenated key+cert for QuaDRA `option cert` |

Locked SAE IDs (certificate CN — see `lab/topology_contract.py`):

| Role | SAE ID |
|------|--------|
| Master (`kme-a`) | `25840139-0dd4-49ae-ba1e-b86731601803` |
| Slave (`kme-b`) | `c565d5aa-8670-4446-8471-b0e53e315d2a` |

### KME API (HTTPS mTLS, TLS 1.3)

From a cEOS switch in **VRF MGMT** (example: master SAE status on `kme-a`):

```bash
docker exec arista-quantum-safe-ceos1-both ip netns exec ns-MGMT curl -sf \
  --tlsv1.3 --tls-max 1.3 \
  --cacert /mnt/flash/kme-ca.crt.pem \
  --cert /mnt/flash/kme-sae.crt.pem --key /mnt/flash/kme-sae.key.pem \
  https://172.20.127.51:8010/api/v1/keys/25840139-0dd4-49ae-ba1e-b86731601803/status
```

Key delivery (`enc_keys` on master KME):

```bash
docker exec arista-quantum-safe-kme-a curl -sk \
  --cert /certs/sae.crt.pem --key /certs/sae.key.pem \
  -H 'Content-Type: application/json' \
  -d '{"number":1,"size":256}' \
  https://172.20.127.51:8010/api/v1/keys/c565d5aa-8670-4446-8471-b0e53e315d2a/enc_keys
```

Automated: `make test-kme`.

## QuaDRA configuration

Templates (rendered by `make gen-topo`):

| Template | Switch | Purpose |
|----------|--------|---------|
| `configs/ceos/quadra-macsec-master.cfg.in` | ceos1-both | Static SAK profile `quadra-master` on Ethernet2 |
| `configs/ceos/quadra-macsec-slave.cfg.in` | ceos3-qkd | Static SAK profile `quadra-slave` on Ethernet1 |
| `configs/ceos/quadra-daemon-master.cfg.in` | ceos1-both | `daemon quadra` master agent |
| `configs/ceos/quadra-daemon-slave.cfg.in` | ceos3-qkd | `daemon quadra` slave agent |

### Static MACsec (pre-provisioned SAK)

Both sides use **static SAK** with **AN 0** (QuaDRA requirement), cipher **`aes256-gcm-xpn`**, and placeholder 256-bit keys until the first rotation:

```text
mac security
   profile quadra-master
      cipher aes256-gcm-xpn
      key source sak static
      secure channel rx
         identifier <rx-sc-id>
         an 0 key <placeholder-rx-key>
      secure channel tx
         identifier <tx-sc-id>
         an 0 key <placeholder-tx-key>
```

RX/TX secure-channel IDs and keys are **mirrored** on the slave relative to the master. This link is separate from **dynamic 802.1X MACsec** on Ethernet1 between ceos1-both and ceos2-pqc — see [MACsec](macsec.md).

### Daemon stanza (master example)

Startup-config renders `daemon quadra` as **shutdown** so nodes boot without the extension. When QuaDRA is installed and started, a typical master configuration looks like:

```text
daemon quadra
   exec /usr/bin/quadra
   option macsec-intf value Ethernet2
   option peer value 10.255.0.6
   option peer-mode value slave          ! CLI value is inverted — "slave" = master role
   option key-rotation value 120s
   option kme value 172.20.127.51:8010
   option kme-vrf value MGMT
   option cacert value /mnt/flash/kme-ca.crt.pem
   option cert value /mnt/flash/kme-sae-bundle.pem
   option peer-sae value c565d5aa-8670-4446-8471-b0e53e315d2a
   option recovery-keys value <rx-placeholder>,<tx-placeholder>
```

| Option | Master (ceos1-both) | Slave (ceos3-qkd) |
|--------|---------------------|-------------------|
| `macsec-intf` | Ethernet2 | Ethernet1 |
| `peer` | `10.255.0.6` | `10.255.0.5` |
| `peer-mode` | `slave` (-> **master** role) | `master` (-> **slave** role) |
| `kme` | `kme-a:8010` | `kme-b:8020` |
| `cert` | `kme-sae-bundle.pem` | `kme-sae-b-bundle.pem` |
| `peer-sae` | Slave SAE UUID | Master SAE UUID |
| `recovery-keys` | rx,tx placeholders | tx,rx (reversed) |

!!! note "`peer-mode` inversion"
    QuaDRA’s `option peer-mode` CLI value is **inverted** relative to the operational agent role. The lab follows Arista’s documented mapping (master switch uses `peer-mode slave`, slave switch uses `peer-mode master`).

### Host placement (lab automation)

After obtaining the `.swix` from your Arista account team, place it on the **lab host** (not inside a cEOS container) before deploy or install:

| Location | Purpose |
|----------|---------|
| `download/quadra/` | **Recommended** — gitignored directory (same area as cEOS tarballs) |
| `QUADRA_SWIX=` | Makefile override when the file lives elsewhere |

**Filename:** keep Arista's delivered name — `QuaDRA-<version>-<arch>.swix`. The lab discovers any version matching that pattern; **do not rename** the file to match a pinned lab version.

| Host architecture | `<arch>` in filename |
|-------------------|----------------------|
| amd64 / x86_64 | `x86_64` |
| arm64 / aarch64 | `aarch64` |

Example (arm64 host):

```bash
mkdir -p download/quadra
cp ~/Downloads/QuaDRA-1.0.10.rel1-aarch64.swix download/quadra/
make gen-topo && make deploy
```

When the swix is present, `make gen-topo` adds Containerlab bind mounts and post-boot install exec on **ceos1-both** and **ceos3-qkd**. On an already-deployed lab, run `make install-quadra` instead (or set `QUADRA_SWIX=/path/to/QuaDRA-<version>-<arch>.swix`).

### Extension install (EOS CLI)

Manual install inside a switch (when not using lab automation):

```text
enable
copy flash:QuaDRA-<version>-<arch>.swix extension:
extension QuaDRA-<version>-<arch>.swix
copy installed-extensions boot-extensions
show extensions
```

Expect QuaDRA listed as available and installed. Then start the agent:

```text
configure
daemon quadra
   no shutdown
end
show daemon quadra
```

## Caveats

| Topic | Notes |
|-------|-------|
| QuaDRA availability | **Not public** — contact Arista account team for the extension and user guide |
| MACsec license | Static SAK MACsec requires a MACsec license on cEOS |
| KME simulator | Open-source lab stand-in; not a production QKD system |
| Startup default | `daemon quadra` **shutdown** in startup-config until extension is installed |
| Dynamic vs static MACsec | Ethernet1 (ceos1 <-> ceos2) uses 802.1X; Ethernet2/1 (ceos1 <-> ceos3) uses QuaDRA static SAK |
| Key rotation interval | Lab default **120 s** on master (`option key-rotation value 120s`) |
